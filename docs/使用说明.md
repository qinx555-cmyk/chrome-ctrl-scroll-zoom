# 通用滚轮缩放 · 使用说明

一个 macOS 菜单栏工具，让支持原生缩放的应用通过 **Control（⌃）＋鼠标滚轮**放大、缩小内容。工具自动检查前台应用菜单，调用应用自己的缩放命令，缩放档位、排版和记忆方式由各应用管理。

v1.1.0 原名“Chrome 滚轮缩放”，现已扩展到具有可识别缩放菜单的应用，包括 Chrome、Edge、VS Code、Codex 等。豆包通过专用的字体缩放菜单适配。没有可识别缩放功能的应用保持原样。

## 下载安装

1. 打开本项目的 [Releases 下载页面](https://github.com/qinx555-cmyk/chrome-ctrl-scroll-zoom/releases/latest)，下载 `ScrollZoom-1.1.0-universal.dmg` 并打开；也可下载同名 `.zip` 并解压。
2. 将 **通用滚轮缩放.app** 拖到 Mac 的“应用程序”文件夹，再从那里打开。
3. 启动后，屏幕顶部菜单栏会出现 **⌃↕**。这是菜单栏工具，不显示 Dock 图标。

发布包为 **Universal 应用，构建目标为 macOS 13 或更高版本**，包含 Apple Silicon 和 Intel 两种架构。Intel 和其他 macOS 版本尚未逐一实机验证。

### 从旧版升级

1. 点击菜单栏 **⌃↕**，退出旧版“Chrome 滚轮缩放”。
2. 移除原来的 **Chrome 滚轮缩放.app**，将新版 **通用滚轮缩放.app** 放入“应用程序”。同时保留两个副本可能导致系统打开旧版。
3. 打开新版并检查辅助功能权限。系统可能要求重新授权；如旧权限项失效，可移除旧项，再用“＋”添加新版应用并开启权限。
4. 如添加过登录项，移除旧项，添加“通用滚轮缩放”。

反转方向偏好沿用旧版设置。GitHub 仓库地址保持不变。

### 首次打开时被系统拦截

此版本使用本地 ad hoc 签名，**没有 Apple Developer ID 签名，也未经过 Apple 公证**。本地签名不代表 Apple 已验证开发者身份或检查过软件。

确认下载来自本项目、愿意信任此软件后，可按 [Apple 官方说明](https://support.apple.com/zh-cn/102445) 操作：

1. 先尝试打开应用。
2. 打开“系统设置”→“隐私与安全性”，向下找到对应提示，点击“仍要打开”。
3. 在再次出现的提示中点击“打开”；如系统要求，在系统窗口完成身份验证。

只为这个应用添加例外即可，无需关闭 Gatekeeper。若系统提示应用已损坏或包含恶意内容，请先停止安装并核查下载文件。

## 开启辅助功能权限

1. 在工具窗口点击“打开辅助功能设置”，或点击菜单栏 **⌃↕** →“打开辅助功能设置…”。
2. 在系统设置中找到 **通用滚轮缩放**，开启其权限；如未列出，可用“＋”添加“应用程序”中的该应用。升级后旧名称可能仍暂时显示在权限列表中，以实际应用路径为准。
3. 如系统要求，在系统窗口完成密码或触控 ID 验证，不要向任何人提供密码。
4. 返回菜单栏，确认工具已启用，再切换到要使用的应用，等待其缩放菜单被识别。

相应页面在部分 macOS 版本中叫“辅助功能”；已测试的 macOS 27 将其显示为 **“设备控制和数据访问”**。授权后工具会自动检查权限，通常无需重启。

## 日常使用

先点击目标应用，使它成为前台应用，再进行以下操作：

| 操作 | 效果 |
| --- | --- |
| 按住 Control（⌃），滚轮向上 | 调用该应用的放大命令 |
| 按住 Control（⌃），滚轮向下 | 调用该应用的缩小命令 |
| 松开 Control 后滚动 | 正常滚动 |
| 菜单栏 →“恢复当前应用默认缩放” | 调用该应用自己的重置命令；未提供时不可用 |

这里的 Control 是 **⌃**，不是 Command（⌘）。同时按住 Shift、Option 或 Command 时，工具不会接管滚轮。许多应用支持 **⌘0** 恢复默认比例，以该应用菜单中显示的快捷键为准。

点击菜单栏 **⌃↕** 可以：

- 查看当前应用是否已识别到缩放能力。
- 取消勾选“启用 Ctrl + 滚轮缩放”来暂停，再次勾选即可恢复。
- 勾选“反转缩放方向”；这个设置会保存在本机。
- 选择“恢复当前应用默认缩放”，使用该应用的原生重置命令（如有）。
- 打开使用说明和权限设置，或退出“通用滚轮缩放”。

## 各应用中的效果

工具从原生菜单中寻找成对的放大、缩小命令。应用版本、界面语言、当前窗口和对话框状态都可能影响菜单识别或命令是否可用。

| 应用 | 使用的原生能力 | 说明 |
| --- | --- | --- |
| Chrome、Edge 等浏览器 | 菜单中的放大／缩小 | 页面比例、网站记忆和最大最小值由浏览器管理 |
| VS Code | 查看 → 外观 → 放大／缩小／重置缩放 | 调整应用自己的界面缩放 |
| Codex | 原生 Zoom In／Zoom Out／Actual Size 菜单 | 具体缩放区域由 Codex 当前聚焦位置决定 |
| 豆包 | 显示 → 放大字体／默认字体／缩小字体 | 专用适配，调整豆包提供的字体大小 |
| 其他应用 | 可识别的原生放大／缩小菜单 | 识别成功后使用；无对应能力时保留原滚轮行为 |

豆包的字体菜单别名只针对豆包。工具不会把所有应用的“增大字体／减小字体”命令当作页面缩放，也不会修改聊天或文档正文的字体格式。

v1.1.0 已由用户使用实体鼠标验收：Edge、VS Code、豆包、Codex 四个应用中，Control＋滚轮向上放大、向下缩小均正常。其他应用及各应用的所有子界面未逐一验收，实际效果仍取决于应用原生能力与设备。

## 重启后运行

默认**不设置开机或登录自启**，重启 Mac 后需要重新打开应用。

如需自动启动，可在“系统设置”→“通用”→“登录项”（部分版本显示“登录项与扩展”）的“登录时打开”列表中，用“＋”添加 **通用滚轮缩放.app**。不再需要时，从该列表移除即可。

## 兼容范围

- 工具只调用前台应用的原生菜单动作。缩放范围和效果由该应用提供：可能是网页、界面、画布或豆包的字体。
- 未找到成对缩放命令、命令处于禁用状态或应用无法提供菜单信息时，保留原滚轮行为。切换应用后会重新检查菜单。
- 原生恢复默认命令为可选能力；部分应用支持放大、缩小，但没有重置菜单。
- 普通触控板捏合保持原有行为。Control＋触控板滚动及连续滚轮采用累积位移换档，并忽略惯性；不同设备的手感可能与 Windows 驱动有所不同。
- 方向会适配 macOS 的“自然滚动”；如果鼠标驱动使方向相反，可使用菜单中的“反转缩放方向”。
- 若 macOS 的系统级缩放也绑定了 Control＋滚轮，请到“系统设置”→“辅助功能”→“缩放”检查冲突，调整系统缩放的修饰键。
- Intel、macOS 13～26、所有应用版本及不同鼠标驱动未逐一实测。浏览器 PDF 或其他特殊查看器的缩放限制由对应应用决定。

## 无法使用时

1. 确认菜单栏 **⌃↕** 已出现，工具已启用，辅助功能权限已开启。
2. 确认目标应用位于前台，使用的是 Control（⌃）键，同时未按 Shift、Option 或 Command。
3. 点击菜单栏查看当前应用的识别状态。切换应用后可稍候片刻，等待菜单检查完成。
4. 若未识别到缩放，打开目标应用的“查看／显示”等原生菜单，确认是否有可用的放大、缩小命令。只有系统窗口最大化的“缩放”命令不属于内容缩放。
5. 若应用的缩放项变灰，先关闭模态对话框，或返回可缩放的主界面。没有原生内容缩放能力的应用保持原样。
6. 若显示等待权限或监听未启动，检查权限后退出工具，再重新打开。更新应用或重新签名后，macOS 可能要求重新授权。
7. 检查系统缩放及鼠标驱动是否也处理了 Control＋滚轮。

反馈兼容问题时，请提供应用名称、版本、macOS 版本，以及原生菜单中的缩放命令名称，便于判断能否适配。

## 隐私与权限

工具订阅 macOS 滚轮事件，用修饰键状态判断 Control＋滚轮；读取前台应用名称、进程信息及原生菜单的标题、层级、可用状态和动作，以识别和调用原生缩放功能。

**不订阅键盘输入，不读取网页、聊天或文档正文，不记录滚轮或按键事件，不发起网络请求。** 仅将“反转缩放方向”偏好保存在本机。v1.1.0 新增的菜单读取用于兼容性检测。

辅助功能是 macOS 提供的较宽权限，上述处理范围由公开源代码实现。

## 卸载

1. 点击菜单栏 **⌃↕**，退出“通用滚轮缩放”。
2. 如添加过登录项，将它从“登录时打开”列表移除。
3. 将“应用程序”中的 **通用滚轮缩放.app** 移到废纸篓。
4. 在系统设置的辅助功能权限列表中关闭或移除该应用；如保留旧版权限项，也一并移除。

退出或卸载后，各应用恢复原有的滚轮行为。此前由应用自身保存的缩放比例可使用各应用的恢复默认功能重置。
